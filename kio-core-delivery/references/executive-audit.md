# 👑 Kio Executive Audit & Final Sign-Off (5-Pillar Quality Gate)

When the user mentions *"Kio"*, *"Kio Agent"*, *"Kio audit"*, *"Kio review"*, or requests a final acceptance review before hand-off, run the **Kio Executive Review** integrating four engines:
- 🎨 **Taste Skill Engine (`kio-frontend-craft`)**: Reviews UI/UX against AI slop, checks the 3 Dials, and eliminates generic purple gradients and cookie-cutter 3-column bento grids.
- 🪢 **Ponytail Lean Engine**: Enforces lean code, removes over-engineering, applies YAGNI, and prefers the standard library and native platform capabilities.
- ⚡ **Superpowers & SDD Engine (`kio-core-delivery`)**: Verifies atomic task breakdown, clean context isolation, and two-stage review (Spec Compliance & Code Quality).
- 🛡️ **Kio Deep Review Engine (`kio-qa-security` → `references/deep-review/`)**: Runs adversarial review, measures impact outside the diff (`blast-radius`), challenges large diffs (`interrogate`), compares parallel candidates (`arena`), and makes recurring bugs impossible (`correct`).

---

## 🔍 The 5-Pillar Executive Audit

1. 🛡️ **Security Audit (Zero-Trust) & Adversarial Defense**: Verify 0 exposed credentials, 100% inputs sanitized, 100% outputs escaped, prepared SQL statements, nonces, and explicit authorization checks. For large diffs (>300 lines) or high-risk areas (auth, payments, migrations), run `kio-qa-security` (`references/deep-review/blast-radius.md`, `interrogate.md`) and prove no out-of-diff breakage with real commands.
2. 🪢 **Code Quality & Ponytail Lean**: 100% production code (0% stubs or `// TODO` placeholders), every source file `< 700 lines of code`, no unused dependencies, strict YAGNI. When a bug recurs, apply `correct` to make it impossible (Architecture ➔ Types ➔ Lint ➔ Tests).
3. 🎨 **UI/UX Taste & Anti-Slop**: High-craft visuals matching `kio-frontend-craft` (`references/ui-ux/pro-rules.md`, `references/unslop-9-pass.md`), clear typographic hierarchy, 4px/8px spacing rhythm, no generic AI templates.
4. ⚡ **Architecture, SDD & Mandatory Feature Test Cases**: Clean separation of logic and layout; **100% of new features or business-logic changes must include automated test cases (Happy Path + Edge Cases + Error Handling) passing 100% green**, passing two-stage review, and complying with `rules/GLOBAL_RULE.md` (Priority #1). Never sign off on a feature without passing tests.
5. 🎯 **Business Alignment**: Meets 100% of the user's stated objectives with zero functional regressions.

## 🚫 Commit & PR Rules (No AI Attribution Footprints)

- **PR description**: Do NOT include `🤖 Generated with [Claude Code](https://claude.com/claude-code)` or any "Generated by AI" footer. Keep only Summary + Test plan.
- **Commit message**: Do NOT add `Co-Authored-By: Claude ...` or any AI attribution trailer. Use only trailers explicitly required by the project.
- This rule overrides default tool attribution. If a PR was created with an AI footer, strip it immediately via `gh api -X PATCH repos/<owner>/<repo>/pulls/<n> -F body=@file.md`.
