# ML conference paper style

This skill reproduces one consistent house style for ML conference papers: the section skeleton, paragraph templates, transitions, notation, experiment write-up, figure palette, table layout and LaTeX project structure. The rules were distilled from a set of published ICLR / NeurIPS / ICML papers, and every rule carries an evidence label that says how strongly the source set supports it. All examples in this skill are synthetic.

| Type | Contribution (`references/paper_types.md`) |
|---|---|
| W | workflow with components: new modules inside a training, agent or inference loop, trained end to end |
| T | objective + constraint, solved in closed form; inference-time or training-free |
| L | new training loss with a theoretical guarantee |
| R | reward or supervision design for RL |
| F | findings: an empirical discovery, possibly followed by a simple method |

**Evidence labels.** `[all]` = every source paper where the rule applies follows it; `[most]` = a clear majority; `[some]` = a minority or a single precedent: an option, never a checklist requirement on its own; `[venue: ICML]` / `[venue: ICLR]` / `[venue: NeurIPS]` = a venue requirement or practice seen only at that venue (all two-column guidance is `[venue: ICML]` and rests on the official ICML kit plus the house two-column layout); `[current]` / `[older]` = practice that changed over time (follow `[current]`); `[fix]` = the skill corrects what the sources did; `[skill choice]` = a template helper or default the skill adds. Unlabelled rules are `[all]` or `[most]`.

**When practice disagrees**: an `[all]` or `[most]` convention is the style. Where practice changed over time, follow `[current]`. A `[current]` rule that another current source contradicts is a preference, not a checklist item. Venue requirements beat style, and the current call for papers beats everything in this skill (`references/venues.md`). Where the sources are wrong (a bug, a font fallback), the skill says it corrects them (`[fix]`).

## Workflow: proposal to finished paper

### Step 0. Confirm the venue, fetch the current call for papers, set up
1. **Confirm the target venue and cycle with the user, then fetch that year's official call for papers, author instructions and style kit** (`venues.md` §1.0). Limits and required statements change every year: ICLR went from 10 to 9 pp (2026) and added a required AI use statement (2027); NeurIPS 2026 added track options; ICML 2027 had no call yet on 2026-09-25. Write the limits and required statements as `%` comments at the top of the main file, and pass `--limit` to `check_paper.py` if they differ from its `VENUES` table. Never reuse last year's `.sty`/`.bst`.
2. Collect the inputs: proposal or method notes, available results (maybe none), prior-work list.
3. Decide the paper type (`paper_types.md`): W workflow, T objective + closed form, L loss + theory, R reward design, F findings. A proposal that introduces a method is a method paper.
4. Create the project. ICLR/NeurIPS: copy `templates/main_skeleton.tex` (for NeurIPS, swap the header using VENUE NOTES A2 in `preamble.tex`) and `templates/chapters/`. ICML: copy `templates/main_skeleton_icml.tex` and `templates/chapters_icml/` (renamed to `chapters/`). Then copy `templates/preamble.tex` and `templates/references.bib`, and add the venue kit (ICML: `templates/venue/icml/README.md`). Rename the main file and the `.bib` to the kit's stem (`iclr2027_conference`, `neurips_2026`, `example_paper`) `[all]`. Build once to confirm it compiles.
5. Source conventions from the first line `[all]`: one sentence per line, never hard-wrapped; replaced wording kept as a `%` line next to the new one, never deleted; labels `sec:`/`apdx:`/`fig:`/`tab:`/`eq:`/`alg:` + lowercase hyphenated words; the `.bib` holds trimmed DBLP entries with short-name keys (`Adam`, `ViT`, `ImageNet`) (`latex_source.md`, `structure.md` §3).

### Step 1. Outline (write it as `%` comments at the top of each chapter file `[some]`)
1. **Pair everything** (rule of two `[all]`): two limitations of the prior paradigm, two components, two objectives, and two named twin concepts (e.g. "coverage / precision" for a data-filtering method; "target fit / prior fidelity" for a label-shift correction; "sharpness / calibration" for a forecasting loss). **Scope**: problems, limitations, components and goals pair; the intro P5 evidence roadmap and the number of RQs follow the experiments (3-4). Write the **one-to-one mapping** as a `%` comment: intro limitation (i)/(ii) ↔ method component (i)/(ii) ↔ Methodology subsection titles ↔ RQ/finding that tests each (`prose.md` §1 rule 1). Introduce the named pair with ONE phrasing per paper: "(termed X)", "By X, we mean ...", or "X, meaning that ..." (`prose.md` §1 rule 10).
2. **One-sentence key idea**: "The key/core idea is to ..." `[most]`. With two components, split it as "(i) ... and (ii) ..." (e.g. "(i) how much weight each example receives and (ii) how many examples each cluster contributes").
3. **Title**: "Verb-ing <Object> with <Key Ingredient>" or "<Hook>: <Descriptive Subtitle>"; sober. **Method name**: an acronym is expanded with bold initials at first use in the abstract, intro P4 and the Methodology opener `[some]` (e.g. `\textbf{D}ifficulty- and d\textbf{IV}ersity-\textbf{A}ware filtering (DIVA)`); a non-acronym name may be bold or plain (`[some]` each).
4. **One epithet** reused throughout (e.g. "cheap and faithful"; "training-free and bounded") `[most]`. Its two words are the negations of the two drawback labels and the two axes of the standard sentence (`contributions.md` D2-D3, KR2-KR3); no third word pair on the problem side. While results are pending, pick a property that holds by construction, never effective / accurate (`contributions.md` C.7). Declare it as `% epithet: <phrase>` next to the concept table so `check_paper.py` counts it in the abstract, Introduction, Methodology opener and Conclusion.
5. **RQ list** (3-4): performance → mechanism → ablation → extension (`experiments.md` §2). Each RQ backs one claim.
6. **Notation table**: every symbol once, calligraphic text objects, hats for generated quantities (`math.md` §1).
7. **Running example** `[most]`: pick one concrete example (a real input, question or prompt) that will appear in at least two places: the teaser, the framework figure, and one sentence in the text (`prose.md` §1 rule 11).
8. **Concept table** (`concepts.md`): list the 2-5 core concepts and ≤6 framing terms as `% concept:` lines. For each, **borrow the established term from the literature and cite it; compose from existing terms if needed; coin only as a last resort (≤2 per paper)**. Record provenance and definition; one concept = one exact phrase for the whole paper, and every core concept is echoed later (Methodology, Experiments, Conclusion).
9. **Term table** (`concepts.md` §3), before any drafting: one row for every key term (concept entries, every "(termed X)", method, component and metric names, recurring technical nouns): exact phrase | meaning in one plain sentence | verdict (borrowed / composed / plain / coined) | source quote (≤ 15 words) + citation key from the **cited papers' own text**, same sense | other senses in the field. Write it as `% concept:` / `% term:` lines. Prefer the cited papers' terms; coin at most 1-2; a "fixed terms" list never exempts a term (fixed = not reworded, not verified); check senses, not spellings (probe, base, pre-registration, seed noise, screening, share-aware, ablation); one thing = one name; re-audit whenever a term is added.

### Step 2. Page budget
1. Pick the blueprint for the venue (`structure.md` §5):
   - **ICLR, 9 pp** `[most]`: abstract ≤250 words; intro 650-750 (~2 pp); Preliminary 350-550; Methodology 900-1,100; Experiments 850-1,000; Limitations 35-55; Conclusion 80-120. Total ≈3,500-3,700 prose words + 6-8 floats.
   - **NeurIPS, 9 pp** `[some]`: ≈3,700-3,850 words.
   - **ICML, 8 pp, two columns** `[venue: ICML]`: ≈3,650-3,900 words fill 8.0 pp with about 12 floats (2.6 pp). Most floats are single-column; only method diagrams and the main table are `figure*`/`table*` (`figures_tables.md` §6.1).
2. List the floats with target sizes: teaser (0.4-0.5 pp one-column; `\columnwidth` at ICML), framework `figure*` (0.4-0.5 pp), main `table*` (0.35-0.5 pp), 2-3 result figures (4-6 column figures at ICML), an optional algorithm (~0.3 pp).
3. Assign every other item to the appendix now (`structure.md` §6-7): Related Works, proofs, full setup, extra models/datasets, sweeps, case studies, statements.

### Step 3. Drafting order
The order follows the dependencies between sections: the intro restates method notation (P4) and names each experiment subsection (P5), and the abstract and conclusion mirror the intro.
1. **Preliminary** (roadmap; task formulation + base paradigm equations; the base-paradigm subsection ends with the limitation the method removes).
2. **Methodology** (the type's plan from `paper_types.md`; roadmap opener; purpose-clause subsection openers; per-term bold run-ins; the last subsection closes the loop; algorithm).
3. **Experiments** (RQ list, setup run-ins, tables at final shape, observation blocks). No data yet → `experiments.md` §7.
4. **Introduction** (5 paragraphs, `prose.md` §3 + the type's P2-P4), with teaser. **Write the chain first** (`introduction.md` §0) as a `%` block of 8-10 one-line claims, and draft only when every link holds: a **root-cause sentence** that names, neutrally, the one design all prior practice shares (after describing that practice in your own notation, with each weakness planted as a neutral detail); the **standard before the weaknesses** ("Intuitively, effective X should be A (\ie ...) and B (\ie ...)"), set before the first "However"; each drawback = mechanism + consequence, violating one property; the **key idea as the literal negation of the root cause** (reuse its content words, flipped); a **challenge sentence** ("However, ..." with a citation) before any component that does not follow from the key idea; the **two axes = the method epithet**, repeated verbatim in the proposal, mapping, benefit and closing sentences. P5 is the First/Second/Third evidence roadmap; **no contribution list** (`contributions.md` D1). Then check IR1-IR15.
5. **Abstract** (`prose.md` §2), then **Limitations** and **Conclusion** (mirror the abstract).
6. **Appendix** (Step 5), then Related Works (Appendix A).
For each paragraph: open the slot template, look at the matching example in `examples.md`, draft, check the density norms (`prose.md` §11) and the sentence rules (§12: one subject per sentence, subject and verb in the first words, the point at the end of the main clause, "we" for method steps and the method name for results), then apply the revision rules (`prose.md` §9).
**Wording** (`prose.md` "Use attested expressions"): pick connectives by function from `prose.md` §4a (preferred tier first; never ref-only or foreign ones) and make every non-first sentence link back (§4b). Take each sentence's wording from `assets/lexicon/lexicon.md`'s section for that rhetorical move, and check any multi-word phrase you are unsure about with `python3 tools/ps.py "phrase" -q` (queries the shipped phrase index; add `--corpus <dir>/corpus.jsonl` to check your own papers instead); prefer core and occasional entries, never retired, banned or ref_only ones.

### Step 4. Figures and tables
1. Plots: `templates/plot_style.py` (`apply()`, one 600-dpi PNG per panel, `save()` also writes a PDF, which ICML prefers); palette blue `#649CD8`/`#BFD8EF`, pink `#FF85A1`/`#FFDAE2`; saturated = ours, tint = baseline (`figures_tables.md` §3-4). Compare with `assets/plots/`.
2. Diagrams in TikZ on `templates/housediagram.sty`, imitating `assets/diagrams/` (`figures_tables.md` §5): copy `templates/diagram_skeleton.tex` to `figures/src/<name>.tex`, set `% target-width-in:` to the printed width of the float, and place every node relative to another (never at hand-computed coordinates). The package styles carry the house look: white rounded modules with 1.1-pt role outlines (rose `trainable`, navy `frozen`), exactly one filled focal module (`hero`), quoted examples in `chip`s, edgeless lanes, the soft Gaussian shadow, notched heads, dashed amber `score flow`, solid amber `feedback flow`, bold sans labels with LaTeX math, a compact `legend row`; `assets/diagram_src/style_sheet.png` names every style. Build with `python3 scripts/render_diagram.py figures/src/<name>.tex --out-dir figures/framework --check` (vector PDF at the printed width + PNG; it fails on Type 3 fonts or a width more than 3 % off the target and prints the clean-palette metrics: white ≥ 0.72, earthy ≤ 0.05, ≤ 3 hue families, mean-sat 0.25-0.75), then open the PNG and fix what you see (wrapped chips, labels on lines, arrowheads off their targets) before including the PDF unscaled. A slide-tool figure is fine if it matches §5.1-5.2.
3. Tables from `templates/tables.tex`; choose the main-table variant by the rule in `figures_tables.md` §7 (T1 / T2 / T4, each `[some]`). Empty cells are `\pend` until real numbers exist.
4. Captions: figures below (title phrase + takeaway; framework captions walk the arrows), tables above.

### Step 5. Appendix and statements
Order: A Related Works → B Theoretical Analysis/Methodology → C Implementation Details → D Prompts → E Additional Experiments (mirror the RQs) → F Analysis/Case Study → venue sections (NeurIPS: Broader Impacts, Asset Licenses, then the checklist, also kept at camera-ready). Each top-level section starts with `\clearpage` `[most]` and uses an `apdx:` label; a main-text paragraph that lost material to the appendix ends with a specific `Appendix~\ref{apdx:...}` pointer. Before the references: ICLR 2027 AI Use Statement (required) + Ethics + Reproducibility statements; ICML `\clearpage` + Impact Statement (required at submission). ICML appendix: `\newpage\appendix\onecolumn` `[venue: ICML]`. Details: `venues.md` §1.5, §1.7.

### Step 6. Compile and page check
1. If the machine has no LaTeX engine or the build tool is unknown, run `bash scripts/check_env.sh` first and follow the install command it prints (all options: README.md "Setup"; without a local engine the user can build on Overleaf). Then `tectonic -X compile --keep-intermediates main.tex` (or `latexmk -pdf`), with network access for the first build. Fix every error, undefined reference and "Missing character". If tectonic times out downloading a font (some fonts, e.g. `cmti9`/`cmsy5`, can time out), run `scripts/tectonic_fetch.sh <dir> --missing-pfb` and add `-Z search-path=<dir>` (`venues.md` §2.3).
2. `python3 scripts/check_paper.py <paper_dir> --stage submission` (from this skill folder; the venue and kit year are detected from the main file, `--venue` overrides, `--limit N` sets the current call's limit, `--vocab PATH` adds the rare-word check against your own word list). It prints prose words per chapter against the blueprint, the page of `\label{main-text-end}` (placed after the Conclusion paragraph), venue checks (statements, checklist, anonymity, ICML float rules), the concept table and echo check, the `== terms` block (missing citation keys or quotes in `% concept:` / `% term:` rows, coined rows above 2, "(termed X)" without a row, sense-clash words such as probe / pre-registered / seed noise), the vocabulary check, cohesion notes (connective share and density per chapter, double lock, approximate isolation, ", so" rate, "(termed" count), lint hits, the `== intro & contributions` block (contribution-list phrasing; "novel" / "first" / "To the best of our knowledge" in abstract, intro and conclusion; "Different from them" / "Our work differs" / "is not our contribution"; sentence-initial "Ideally,"; "we argue"; intro and abstract paragraphs ending on a reservation; the `% epithet:` count in abstract, Introduction, Methodology opener and Conclusion; strong result verbs while tables hold `--` / `\pend` cells), and the `== habits` warnings with line numbers.
3. The main text must end exactly on the limit page, and that page must be full `[all]`: never a half-empty last page, never an overflow. Too long → move material to the appendix, tighten floats with negative `\vspace` inside floats only, toggle `% \clearpage`. Too short → bring back appendix material (a second model size, a mechanism figure). Never `\small` body text, shrink fonts, or put negative `\vspace` at headings.
4. Look at the rendered pages. The teaser should sit at the top of p2 in one-column venues and at the top of the right column on p1 at ICML. The skeletons force this with `\suppressfloats[t]` `[skill choice]` (a template helper, not source practice). Also check: no floats overlapping, no table text larger than body text (`\resizebox` enlarges narrow tables; use `\shrinktofit`), and at ICML no `figure*` stranded after the page it belongs to.

### Step 7. Self-review
Go through the checklist below and the checklists at the end of `math.md`, `experiments.md` and `figures_tables.md`; for the Introduction, Related Works and every contribution sentence, run the rule checks of `introduction.md` §6 (IR1-IR15) and `contributions.md` E (KR1-KR14). Then run the revision rules (`prose.md` §9) over every paragraph. Read the `== cohesion`, `== habits` and `== sentences` blocks of `check_paper.py` (rewrite every listed sentence or confirm it matches the source shape, `prose.md` §12d): fix each habit warning with the listed alternative (or confirm it is a legitimate sense), bring chapters below the connective targets up with bridges and double locks, and label the Experiments sentences C/A/L/S/N by hand if the approximate isolation rate is high. Finally grep for leftovers: `\pend`, `[Expected]`, `\figplaceholder`, `<...>`, `Placeholder-`.

## Style rules checklist

Venue (`references/venues.md`)
- [ ] The current year's call, author instructions and kit were fetched at Step 0 and re-checked in the deadline week; the limits and required statements are recorded at the top of the main file.
- [ ] Required statements are present and placed per the kit: ICLR 2027 AI Use Statement before the references; NeurIPS checklist after the appendix, every "Yes" backed by text; ICML Impact Statement (unnumbered, before the references). At submission: no acknowledgements, anonymous code link, self-citations in the third person, no `\iclrfinalcopy`/`[final]`/`[accepted]`.
- [ ] Citation commands match the venue: ICLR `\citep{}` + `\Eqref{}`; NeurIPS `\cite{}` numeric + "Equation~\ref{}"; ICML `\cite{}` or `\citep{}` (the sty maps `\cite` to `\citep`; one argument only; multiple keys in chronological order) + "Equation~\ref{}".
- [ ] ICML `[venue: ICML]`: `[T1]{fontenc}` loaded (otherwise Latin Modern fallback); no `wrapfigure`; no `\textwidth` in column floats; `figure*`/`table*` only for method diagrams and the main table, sourced one page before they print; displays broken with `aligned` to fit 3.25 in; `\printAffiliationsAndNotice{}` called.

Concepts (`references/concepts.md`)
- [ ] Concept table exists (main file, after `\input{preamble}`): `% concept: phrase | core/framing | borrowed: citekey "quote" / composed: parts with citekeys / coined | definition`; 2-5 core (max 6) + ≤6 framing.
- [ ] Term table (`concepts.md` §3): every key term (concepts, each "(termed X)", method / component / metric names, recurring technical nouns) has a `% concept:` or `% term:` row with a citation key and a quote (≤ 15 words) read in the cited paper's own text, same sense; ≤ 2 coined rows; no term exempted as "fixed"; no sense-clash word (probe/probing outside linear probes, pre-registered, seed noise, base update, share-aware); re-audited after every rename; `check_paper.py` `== terms` shows no missing source.
- [ ] Borrowed before coined: every marked term that exists in the literature uses its established wording and is cited at first use; ≤2 coined terms, introduced once with "(termed X)" and built from existing vocabulary (e.g. *budget score*, built from the established "sampling budget"). "(termed" count ≤ number of core concepts; the named pair uses one of "(termed X)" / "By X, we mean ..." / "X, meaning that ..." for the whole paper.
- [ ] Marked only at first mention in the Introduction and at the first formal definition (most marks, over three quarters, are in the Introduction; none in abstract, experiments, conclusion, appendix, captions, headings); 8-15 marks (cap 20); no bold/italics on top of the colour.
- [ ] Consistency: the same phrase, abbreviation and symbol for a concept everywhere (text, figures, captions, section titles); no synonyms after first use.
- [ ] First-use explanations (`prose.md` "Explain at first use; no jargon"): no jargon a cold reader cannot parse; every non-obvious term gets "(\ie ...)" or "(termed X)" at its first occurrence (abstract and Introduction each), then stays unchanged. The explanation sits inside the sentence that carries the link (parenthesis or final clause), never as a separate sentence between a claim and its continuation.
- [ ] Plain words (`prose.md` "Plain words, no coinage"): no coined compound or rare word outside the core concepts; hyphenated compounds ≤41 per 1,000 main-text words (source papers: about 14-41, median about 27); review the lint's rare-word list when a `--vocab` file is given.
- [ ] Echo: every core concept reappears, same phrase and unmarked, in Methodology headings/text, the Experiments RQ text or findings, and the Conclusion.
- [ ] One colour (orange `\concept{}`) ON while drafting/reviewing; `\showconceptsfalse` for the submitted PDF (black, as in every source paper).

Structure
- [ ] Skeleton: Abstract → Introduction (teaser) → Preliminary → Methodology → Experiments → Limitations → Conclusion; Related Works in Appendix A `[most]`.
- [ ] No contribution bullet list, no "rest of the paper is organized" paragraph `[all]` (drafts that had them deleted them).
- [ ] The Methodology opens with a roadmap naming its subsections: "We first ... After that, ... Then, ... Finally, ..." `[all]`; so does the Preliminary `[current]`. The Introduction has none; the Experiments section opens with the RQ list.
- [ ] The base-paradigm subsection ends with the limitation the Methodology removes `[all]` (a later background subsection, if any, follows it).
- [ ] One-to-one mapping `[most]`: intro limitation (i)/(ii) ↔ method component (i)/(ii) ↔ Methodology subsection titles ↔ RQ/finding, same order and same phrase at every link; the P5 roadmap and the RQ count follow the experiments, not the rule of two.
- [ ] The Methodology ends with the subsection that closes the loop: the assembled method, the joint optimization with its algorithm, or inference-time behaviour.
- [ ] Experiment subsections: prefer "(RQk) Noun Phrase" `[current]`; the suffix form `[older]` is not wrong; one form per paper. Intro P5 has one "(\cf Section~\ref{})" sentence per subsection, in the same order `[current]`.
- [ ] Limitations: its own numbered section before the Conclusion `[most]`; 2-3 sentences, two items ("On the one hand ... On the other hand ..." is preferred `[current]`). Conclusion: one paragraph of 80-140 words that mirrors the abstract `[all]`.
- [ ] Every equation needed to re-implement the method is in the main text; proofs, full setup and extra results go to the appendix, each with a specific pointer `[all]`.

Introduction logic (`references/introduction.md` §6)
- [ ] The chain was written first as a `%` block (`introduction.md` §0) and still matches the prose.
- [ ] Root cause (IR1): one neutral sentence names the design all prior practice shares, before or as the first sentence of the criticism `[most]`; each drawback's mechanism reuses a noun phrase from it, and each drawback has a planted source phrase in the prior-work description (IR2) `[most]`.

Prose

- [ ] Rule of two: problems, limitations, components, objectives as "(i) ... and (ii) ..." pairs `[all]`.
- [ ] Running example `[most]`: the same concrete example appears in at least two places (teaser, framework figure, one sentence in the text).
- [ ] Every problem sentence is followed by a remedy sentence ("To this end / To address this, we ...") `[all]`.
- [ ] Second sentence of a paragraph: "Specifically, ..." `[all]`. Definitions and examples go in parentheses: `(\ie ...)`, `(\eg ...)` `[all]`.
- [ ] Cohesion (`prose.md` §4b): every non-first sentence links back (connective, anaphor, repeated noun or structure); ≤ 5% unlinked (Intro/Method ≤ 3%); connective-led share 45-55% (Intro ≥ 55, Method ≥ 45, Experiments ≥ 35), ~2.2 per 100 words; connective + this/these/such at every problem → solution turn; ≥ 3 shell nouns ("This crowding ...") per Introduction; every paragraph opener links back; RQ subsections open with a bridge and end with a conclusion, not an appendix pointer; "It/Its/This" only for the previous subject; ", so" + clause ≤ 1 per 1k words.
- [ ] Connectives chosen from `prose.md` §4a: preferred tier first; no older-style (Hence, Thus, Towards this end, As such, In particular, Clearly, In a nutshell, One possible reason ...) and no foreign ones (Ideally, Nor, likewise, is not free, empirical question, whenever).

- [ ] Page-fit cuts kept every link-carrying clause; the sentence after each cut re-checked for a link (`prose.md` §9 rule 17).
- [ ] Emphasis is bold only `[all]`: bold run-in heads `\textbf{Head.}` (no `\paragraph` `[most]`), bold full-sentence findings after "We have the following observations:" `[most]`, at most one bold-italic research question `[some]`. Italics only for a term at its definition `[some]`; no takeaway boxes.
- [ ] Tense: present for the method, experiments and findings in the main text `[all]`; the Conclusion in past `[most]` or present `[some]`, one tense per paragraph (`prose.md` §10).
- [ ] Density: sentences of median 20 words, ≤7% of 40+ words `[all]`; split any clause of 40+ words `[some]`; bold findings 8-20 words; sentences per paragraph by section in `prose.md` §11.
- [ ] Sentence structure (`prose.md` §12) `[all]`: section means within range (Abs/Intro ≤ 26, Method ≤ 27, Exp ≤ 21 words), ≤ 1 sentence of 45+ words per section, a long sentence followed by a short one; one subject per sentence (two main clauses ≤ 15%), ≤ 10 words before the subject, relative clauses at the end, ≤ 1 parenthetical per sentence; "Since" openers ≤ 2%, This/These/Such openers ≥ 5% in Intro and Experiments.
- [ ] Subject consistency (`prose.md` §12b) `[all]`: we = method steps, the method name = results, one component = its paragraph, This/These = handover; every switch is derived, linear, an anaphor or a parallel contrast opener; no prior-work sentence between two sentences about our method.
- [ ] Emphasis (`prose.md` §12c) `[most]`: the point is in the main clause and at the end; our side of a contrast in the main clause, the baseline in a final "while" clause; no result inside a "Since" clause, a parenthesis or a final "which" clause; pointer endings ≤ 12%, no stacked "(termed)" + citation + pointer tails; no fragments or clefts.

Never "always", "state-of-the-art", "SOTA" (absent from `[current]` papers). About 3 hedges and 2 boosters per 1k words (`prose.md` §4b rule 9).
- [ ] Banned: delve, elucidate, underpin, furnish, Surprisingly, sheds light, Furthermore, Notably, To be specific (`prose.md` §8). Avoid a bare "Here," that adds nothing `[some]`; "Here, X denotes ..." stays fine `[some]`.
- [ ] Precise verbs over verb + adverb `[some]`: endow, mitigate, impede are used widely `[most]`; augment, amplify `[some]`.
- [ ] Terminology unified across text, figures and symbols (a frequent revision target `[some]`).
- [ ] Method name typed literally (no macro); references typed by hand with a tie: "Figure~\ref{}", "Table~\ref{}", "Section~\ref{}", "Appendix~\ref{}", "Equation~\ref{}"; no cleveref `[all]`. The sources mostly type a plain space; the tie is a `[fix]` that only prevents a line break before the number.
