# Draw the organization chart
Check reporting lines against the project roster. For the board, match the actual deliveries to their review records to see what passed, what was sent back, and who owes the next action. Show where evidence is missing. Chinese headers are `岗位`, `部门`, `汇报给`, `派驻`, `怎么调用`, `做什么`, `交付写进`. English headers are `Role`, `Department`, `Reports to`, `Assigned`, `How to call`, `Does`, `Delivers to`. Columns may be reordered, but none may be missing or duplicated. A reporting target must be another role or the reserved human member, written as `Human` or `人`. Escape a literal pipe inside a cell as `\|`.

Run from the skill package root, replacing the input and output paths. If the output already exists, check whether a new version should be created first. The paths below are for an English project; for a Chinese project, follow its project card and use its existing Chinese filenames:

```bash
python -X utf8 skills/fleet-chart/scripts/fleet_chart.py /path/to/my-project/fleet/members.md -o /path/to/my-project/fleet/chart.md
```

The script uses only the Python standard library and requires Python 3.9 or later. Missing columns, duplicate role names, unknown reporting targets, cycles, and unreadable files produce exit code 2 and a short explanation. Check the source table first; do not change reporting relationships just to make a chart render. For an undecided relationship, show the affected role and why a decision is needed, then ask the human here to reply for that role only, such as “Analyst reports to Project manager”. Check that the target exists and the relationship introduces no cycle, record the confirmed relationship, and rerun. If it still fails, explain the next specific issue without asking again from the beginning. Success returns 0. Omit `-o` to write to the terminal.

Place all members inside one organization frame, including the human. Choose the chart language from the roster headers: Chinese headers produce the title “AI 舰队” and node “人”; English headers produce “AI Fleet” and “Human”. Do not put both languages in one label. Arrows run from the reporting target to the role. Labels show the role, department, and assignment; invocation commands and delivery paths stay out of the chart. The script escapes user text as Mermaid entities so it cannot become diagram syntax.

Open the generated Markdown and compare every role against the source table, then inspect it in a Mermaid-capable reader. Check that reply against the source table before continuing. Return the file and check results. If no rendering was performed, say that only the source text was checked.

Generate the four-part local board from the package root with `python -X utf8 skills/fleet-chart/scripts/fleet_board.py --project <project-directory>`. Project filenames select `fleet/board.html` for English or `fleet/看板.html` for Chinese, defaulting to Chinese when unknown; `--lang zh|en` overrides detection. Needs you sorts requests by their leading date; undated text uses the full width without a label, explicit no-action notes stay in an expandable list and do not count as waiting, and member cards show the assignment before its first Chinese or English semicolon with the full text in a tooltip. Work in progress reads roles, assignments, states and recorded start/end times from briefs, deliveries, logs and reviews. The board marks a delivery “Received” only when the deliverable itself exists. If only a `-notes.md` or `-说明.md` file exists, the board shows any incomplete or blocked status recorded on the first line of the notes file. If the notes say “Complete” and the deliverable is missing, the board still does not mark the delivery “Received”. A latest rejected review stays here in red as Returned. Done includes only deliveries whose latest review passed within the last seven days, and its weekly count includes only those tasks; first-pass rate is hidden without explicit evidence. Use `--today YYYY-MM-DD` to fix the window including that day. When no written date exists, delivery file time is noted beside the count. The Roster section lists the fleet members, marks dispatched/running roles Busy and links an existing full chart. Execution ended, delivery received and review passed are separate checks. The standard-library script generates one offline HTML file; run it again after files change.

## Weekly cards and images

Use the bundled skill scripts to generate and check cards and images; never create generation or check scripts in the human's project. Run temporary checks as inline CLI commands or in the system temporary directory, leaving no check scripts in the project.

When someone asks for a weekly card, run this from the package root:

```bash
python -X utf8 skills/fleet-chart/scripts/fleet_weekly.py --project <project-directory>
```

The page goes beside the board: `fleet/weekly.html` for English or `fleet/周报卡.html` for Chinese. Language detection follows the board; `--lang zh|en` overrides it. Use `--today YYYY-MM-DD` to fix the last 7 days, including that day; it computes from the records retained now, rather than reconstructing a past project snapshot. For example, to check a past week, pass that week's last day as `--today` rather than inventing review dates. Open the page, check the project name, date range, model count and evidence for each metric, then choose “Save as image” to save a PNG. The page also offers a PNG preview for saving when the browser does not download directly.

The four metrics reuse the board's reading of briefs, deliveries, reviews and the project card, and also read the existing decision log. Explicit links in existing project documentation can provide first-review evidence as well. Tasks completed counts tasks whose latest review passed within the window, counting revisions of one task once. First-pass rate is the number of this window's passed tasks explicitly recorded as passing their first review, divided by all tasks that passed review within the window. First-review declarations include explicit report markers such as “Review round: 1” or “审核轮次：1”, and Markdown links in the project's existing `README.md` or `README.zh-CN.md` labeled “First review”, “Initial review”, “第一轮审核” or “首次审核” that point to an existing fleet review report. Merge duplicate declarations of the same report; conflicting declarations or missing first-review evidence leave the rate unknown, and a zero denominator never produces a percentage. A returned review does not establish that it was the first review. Do not infer review dates from README prose or tables; keep the dates read by the board and identify any use of file time.

Issues caught counts only required changes from failed reviews within the window, excluding suggestions. When a report has a review table, count rows explicitly marked “Failed” or “不通过” and do not count the later correction list again. Otherwise, use an explicit “Required fixes” or “必修项” list, excluding entries marked as suggestions or optional. In a general “Issues” or “问题” list, count an entry only when it explicitly says a change is required, using words such as “must” or “必改”. Correction substeps and ordinary checklist items are not new issues. For example, a review table with two rows marked “Failed” contributes 2; an item in its required-fixes section that only suggests shortening the draft adds nothing.

Times you were asked adds two existing sources: entries in `fleet/decisions.md` (or Chinese `fleet/决定.md`) within the window that explicitly name the human as decision maker, plus new requests dated within the window and still present in the project card's “Decisions needed” section. Count each decision entry once, read its date from the heading, and require “Decision maker” or “谁定” to identify “Human”, “User”, “人”, “用户”, “使用者” or “人类”. An entry that also names a project role still counts once when the human's decision is explicit. Exclude decisions made only by models or project roles, entries outside the window, and notes explicitly requiring no action. If a decision maker or valid date is missing, the exact total is unknown; count complete, valid records within the window as a lower bound and show “≥N” when N is at least 1, or “—” when N is 0, explaining how many records were omitted and why. Show “No records yet” only when neither source has records. The decision log can preserve answered requests removed from the project card; older requests omitted from that log cannot be recovered, so this metric describes the records available rather than every interruption.

Use short, plain explanations on the card and PNG. When records exist but evidence is incomplete, show “—” and explain why, except for the lower bound allowed for Times you were asked; never substitute zero for an unknown value. Put detailed notes on source files, counting rules and evidence gaps in the HTML below the card, outside the exported PNG. If a record has no written date and delivery file time is used instead, identify that date source in the notes. The model count deduplicates the assignment identifier before its first Chinese or English semicolon. Explicit aliases such as “Model A: …” are merged by alias; role counts and tool names do not establish model vendors.
