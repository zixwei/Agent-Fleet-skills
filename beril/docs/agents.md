# Agent files

Beril ships an entry file for the common coding agents. Each one is a short router to `SKILL.md` and the matching reference. The deep material stays in this repository.

| Agent | File | Loaded by |
|---|---|---|
| Claude Code | `CLAUDE.md` | automatic at project root |
| OpenAI Codex / generic | `AGENTS.md` | automatic for agents that follow the standard |
| OpenAI explicit | `OPENAI.md` | alias for setups that look for it |
| Gemini CLI | `GEMINI.md` | automatic at project root |
| Cursor | `.cursor/rules/beril.mdc` | rule with `alwaysApply` |
| Windsurf | `.windsurf/rules/beril.md` | always-on rule |
| Cline | `.clinerules/beril.md` | project rule |
| GitHub Copilot | `.github/copilot-instructions.md` | repository instructions |
| Aider | `.aider.conf.yml` | read list |
| LLM crawlers | `llms.txt`, `llms-full.txt` | `llms.txt` convention |

## Use inside Beril

No setup. The files are at the repository root and load when the agent opens the project.

## Install into another project

```bash
./scripts/install_agent_files.py --target ~/code/myapp --agents claude,cursor,copilot
```

`--agents all` copies every file. The script refuses to overwrite without `--force`. It adds the absolute Beril path to the top of each file so the agent knows where `./beril` lives.

The request-to-report flow is in `docs/break-my-app.md`.

## Keep them short

The entry files should answer four questions: where is Beril, what is the workflow, what are the hard rules, and where is the artifact reference. Do not paste the whole skill into five files. Five copies drift.

## Update

When the workflow changes, edit `AGENTS.md` first, then mirror the change in the other entry files. `llms-full.txt` is generated by `scripts/build_llms.py`.
