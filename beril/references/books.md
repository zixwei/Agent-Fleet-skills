# Reading canon

Books age. The ones below teach a model that outlives a tool version. Read the chapter that answers your current question, not the whole book.

## Web

| Work | Why | Note |
|---|---|---|
| The Web Application Hacker's Handbook | The classic testing model | Old tools, durable classes |
| Real-World Bug Hunting | Logic and bounty thinking | Read the case studies |
| Bug Bounty Bootcamp | Program workflow | Useful first month |
| OWASP WSTG | Checklist and vocabulary | Free, keep it open |
| PortSwigger research | Current primitives | Read the primary posts |
| PayloadsAllTheThings | Payload memory aid | Confirm the parser |

## Papers and venues

- USENIX Security, CCS, NDSS, S&P for academic primitives.
- Black Hat and DEF CON archives for industry work.
- Project Zero blog for disclosure craft.
- PortSwigger Research for web primitives.
- Google Project Zero, watchTowr, Horizon3 for appliance research.

## How to read

1. State the question before opening the text.
2. Read the abstract, headings, and conclusion first.
3. Read the method twice. Take notes in your own words.
4. Reproduce one figure, request, or lab.
5. Write three lines: what it claims, what it proves, what it misses.
6. Add a drill to `references/exercises.md` if the gap is yours.

A book you cannot reproduce is a podcast.
